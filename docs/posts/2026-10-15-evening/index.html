The context window on the box is not the one you get

A model advertised at 10,000,000 tokens stops being reliable somewhere near 1,000. That gap is not a bug report — it is the vendor's own number measured against an independent benchmark, and it changes how you should budget context.

analysis2026-10-15·3 min read·on Instagram

Every frontier model is now sold on the size of its context window. Two million tokens. Ten million. The number is printed on the box because it is the easiest thing to compare.

It is also close to meaningless, because "fits in the window" and "the model still reasons over it" are different claims, and only the first one is being advertised.

Effective length

Adobe Research's NoLiMa benchmark proposes a definition worth adopting: effective length is the longest context at which a model still holds 85% of its own short-context score.

Note the shape of that metric — it compares a model against itself, not against other models. It is not asking "is this model good?". It is asking "at what length does this model stop being as good as it already was?" That makes it hard to game with raw capability.

The results are not subtle.

At 32K tokens — a length most people consider routine — 11 of 13 models tested scored half or less of their own short-context baseline.

Why the gap is this wide

Needle-in-a-haystack tests, the ones that produced all those "perfect recall at 1M tokens" charts, usually plant a verbatim string and ask for it back. That is a retrieval test, and attention is genuinely good at exact matching over long spans.

NoLiMa removes the literal overlap. The question and the answer share meaning but not wording, so the model has to do an associative hop rather than a string match. Performance falls off a cliff — which tells you the earlier charts were measuring search, not comprehension.

This matters for agents specifically, because almost nothing an agent does is a verbatim lookup. It reads a log and infers a cause. It reads a diff and infers an intent. Those are exactly the associative hops that degrade first.

Treat context as a budget

The practical reframe: context is not a bucket you fill until it overflows. It is a budget you spend, and the exchange rate gets worse the more you spend.

  • Measure your own effective length. Your workload is not the benchmark. Take a task you actually run, double the context, and see whether quality holds. Do it once and you will have a number worth designing around.
  • Retrieve the 5 facts, don't paste the 50 pages. Dumping a whole document is the lazy option and it actively degrades the reasoning you wanted.
  • Compact at half the window, not at the error. If you wait for a context-length error you have been operating in the degraded zone for a long time already.
  • Match the question's wording to the source. Literal overlap is the thing long-context attention is still reliably good at. Where you control the phrasing, use it.
  • Fresh context per subtask beats one long thread. A new window per step costs tokens; a degraded window costs correctness.

The uncomfortable part

If effective length is roughly 1–8K for most models, then a large share of long-context architecture built in the last two years is decoration. The window accepted the tokens. Nobody checked whether the answers got worse, because the request did not fail — it just quietly got less right.

That is the failure mode worth internalising. A context window does not throw an error when you overfill it. It degrades silently, and silent degradation in an unattended agent is indistinguishable from the thing working.
