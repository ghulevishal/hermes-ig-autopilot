Postgres 19 slipped *seven weeks*

After the beta period began, PostgreSQL reverted 8 to 10 significant features. A normal cycle reverts about one.

  • Release moved from early October to around 19 November
  • Some reverts landed very late in beta
  • Driven by LLM-assisted code review finding real defects

This was *not* vibe coding

The committer's own assessment: the reverted code was human-written, much of it years ago, by experienced contributors.

  • The code did not get worse
  • The review got better
  • The quality bar moved AFTER the code was merged

You're staring at a list of like forty defect reports. Even if each requires only a three-line fix, there is a fixed overhead to dealing with each of these, and then you run out of time.

The bottleneck *moved*

Finding defects stopped being the hard part. Having the hours to fix them became the hard part.

  • Detection scaled. Human repair capacity did not
  • A 3-line fix still costs triage, patch, test, review
  • Forty small fixes beat one big one - at the schedule

Before you add AI *to review*

The tool is worth having. Plan for what it produces.

  • Run it on old code BEFORE you promise a date
  • Budget fix capacity, not just scan coverage
  • Triage by severity or you will fix trivia first
  • Decide up front what ships with known defects

Finding is cheap now. Fixing isn't.
