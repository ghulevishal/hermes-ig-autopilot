Which AI model for which task — a routing table for October 2026

One finished task costs $5.98 on the top-ranked model and $0.72 on a model six index points below it. The frontier is now a tight cluster, so the useful question stopped being which model is best and became which model for this job.

analysis2026-10-18·4 min read·on Instagram

In October 2026 the sensible way to choose a model is no longer to read a leaderboard top-to-bottom and take the first row.

Here is why, in two numbers. On the Artificial Analysis index, one finished task costs $5.98 on Claude Opus 5.5 and $0.72 on GPT-6.1 Sol. Opus scores 58 on that index. Sol scores 52.

Eight times the cost for six points. Whether that is worth it depends entirely on what you are doing, which is the whole argument of this piece.

The cluster got tight

For most of the last two years, rank and price moved together: the best model cost the most, and paying more bought you measurably more capability. That stopped being true somewhere around the middle of this year.

Claude Sonnet 5.5 and GPT-6.1 Sol both sit at $2/$10 per million tokens and score within a few points of models priced at $10/$50. The top of the market is a cluster, not a ladder, and the differences between its members are now mostly about shape — what each one is good at — rather than raw capability.

That makes "which is best" close to meaningless and "which for this task" the only question worth asking.

How to actually route

You do not need a routing framework, a gateway product, or an abstraction layer. You need three tiers and the discipline to use them.

Cheap tier. Classification, extraction, summarising, first drafts, anything where the output is consumed by more code rather than by a person. This is the majority of calls in most real systems and it is where almost all the savings live.

Main tier. The work the user actually sees. Quality matters here and the cost difference between tiers is small relative to the value of the output.

Hard tier. Escalation only — reached when the main tier fails a check you defined, not whenever the model feels uncertain. If you cannot name the check, you do not need the tier.

In practice this is three environment variables and a conditional, not an architecture. The hard part is not the plumbing; it is being honest about which tier a given call belongs in, because the comfortable answer is always "use the best one".

Before you switch anything

An index is not your workload. Benchmarks measure what they measure. A model that leads on agentic coding may be mediocre at your particular flavour of it.

Keep twenty real tasks as a test set. Twenty genuine inputs from your own system, with known-good outputs, beats any public leaderboard for deciding what to deploy. Run them when you change models, the same way you would run tests when you change code.

Score cost per finished task, not per token. A cheaper model that needs two attempts, a longer prompt, or a repair pass is not cheaper. Per-token pricing is an input; per-task cost is the number that hits your bill.

Re-check quarterly. This table moved twice in the last six weeks: Gemini 4 Argon went from limited trusted-access to general availability on 13 October, and Anthropic cut Haiku 5.5's price on 7 October. Anything you decide today has a shelf life measured in weeks, so write the decision down somewhere it can be revisited rather than burying it in a config file nobody opens.
